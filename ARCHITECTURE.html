🏗️ Architecture NOIA

Intelligence partagée du service public local

1
🎨 Interface Utilisateur
Interface web moderne et responsive hébergée sur OVH. Design épuré inspiré de Génial (Dalloz). Chat conversationnel intuitif avec suggestions et réponses structurées.
Technologies : HTML5, CSS3, JavaScript vanilla
↓
2
🔒 API Proxy (Sécurité)
Point d'entrée unique qui masque le webhook Make.com. Gère la validation des entrées, le rate limiting (30 req/h), la protection contre les injections, et la sanitization.
Technologies : PHP 7.4+, PDO, cURL
↓
3
💾 Bases de données MySQL
Deux tables : base_centrale (règles communes à tous) et base_locale (documents spécifiques par commune). Recherche full-text optimisée pour des résultats rapides.
Technologies : MySQL 5.7+, Index FULLTEXT, PDO prepared statements
↓
4
⚙️ Make.com (Orchestration)
Scénario d'automatisation qui reçoit la question + résultats de recherche, les transmet à OpenAI avec un prompt structuré, et renvoie la réponse formatée.
Modules : Webhook → OpenAI → Webhook Response
↓
5
🤖 OpenAI GPT-4
Intelligence artificielle qui analyse les sources documentaires et génère une réponse structurée avec : références juridiques, analyse, application pratique, et proposition d'acte.
Modèle : GPT-4-turbo ou GPT-4o
↑
6
📊 Réponse structurée
La réponse remonte par Make → Proxy → Interface utilisateur. Affichage en HTML formaté avec sections claires et références citées.
Format : HTML structuré avec classes CSS spécifiques

💡 Points clés de l'architecture

  • Stateless : Aucune session, aucune conversation stockée
  • Scalable : Peut gérer plusieurs communes indépendamment
  • Modulaire : Chaque composant peut évoluer séparément
  • Sécurisé : 10 couches de protection des données
  • RGPD-compliant : Aucune donnée personnelle traitée
  • Performant : Temps de réponse moyen ~2-3 secondes
  • Économique : Hébergement mutualisé + API usage-based
